# whether_weather

# 출사를 위한 전국 웨더맵 (시간별 기상 인터랙티브 지도 웹앱)
> 기상청 단기예보 격자 데이터를 기반으로 전국 시·군·구 단위의 시간대별 출사 적합도를 시각화하는 인터랙티브 SVG 지도 웹 서비스.

---

## 1. 개요 및 기획 의도
* **핵심 기능:**
  * 시간대별(새벽 4시 ~ 밤 12시) 타임라인 슬라이더 조작에 따라 전국 지도가 실시간으로 리색칠(SVG 히트맵)됨.
  * 풍속, 습도, 운량을 결합한 **"출사 지수(운해/일출/은하수 모드)"** 필터링.
* **타깃 사용자:** 풍경/천체/일출몰 사진가 및 주말 드라이브/캠핑 유저.

---

## 2. 데이터 파이프라인 & 기술 스택
1. **행정구역 벡터 데이터:**
   * 대한민국 시·군·구(약 250개) GeoJSON 경량화 (`topojson` 변환으로 1MB 이하 압축) -> SVG 패스로 렌더링.
2. **기상청 격자 API 연동:**
   * 기상청_단기예보 조회서비스(VilageFcstInfoService_2.0).
   * 250개 시군구 Centroid 위경도를 기상청 격자(nx, ny)로 1:1 매핑.
3. **데이터 캐싱 구조:**
   * GitHub Actions (3~6시간 주기 자동 갱신) -> Python 스크립트로 전국 데이터 크롤링 -> `weather_latest.json` 커밋.
4. **프론트엔드:**
   * Vite + React or Svelte + D3.js (또는 순수 SVG + CSS 그라데이션 트랜지션).

---

## 3. 핵심 기능별 개발 로드맵 (MVP)
* **Step 1:** 대한민국 시군구 SVG 지도 띄우기 (마우스 호버 시 지역명 툴팁).
* **Step 2:** 기상청 단기예보 격자 매핑 테이블 구축 및 샘플 JSON 수집.
* **Step 3:** 타임 슬라이더 구현 (시간 이동에 따라 하늘상태/강수량으로 SVG 채우기 색상 전환).
* **Step 4:** 사진가 전용 특화 필터(운해 확률, 일몰 노을 지수, 야간 은하수 맑음도) 알고리즘 적용.

## 4. 구현 방향 (1차 아이디어 보완)

### 4.1 목표 재정의
* **용도 확장:** 출사뿐 아니라 데이트/나들이 장소 탐색까지 포함. 지수 모드를 `운해 / 일출·일몰 / 은하수 / 나들이` 4종으로 둔다.
* **해상도:** 광역시·도 단위가 아닌 **시·군·구(약 250개) 이상**으로 세분화. 광역 단위로만 나오는 중기예보(3~10일)는 보조로만 쓰고, 격자(5km) 기반 단기예보를 주 데이터로 삼는다.
* **개인화:** 네이버 지도에 저장한 출사 후보지를 입력받아, 선택한 날짜·시간대에 날씨가 좋은 후보지를 순위로 추천.

### 4.2 핵심 설계 결정
| 항목 | 결정 | 이유 |
|---|---|---|
| 런타임 구조 | 백엔드 없는 정적 사이트 + 주기적으로 갱신되는 JSON | 운영 비용 0, API 키가 브라우저에 노출되지 않음 |
| 날씨 데이터 키 | 시군구가 아니라 **격자 `(nx, ny)`** 를 기본 키로 저장 | 시군구 색칠과 임의 좌표(저장 장소) 조회가 같은 데이터를 공유 |
| 수집 방식 | 1차: 단기예보 `getVilageFcst`를 고유 격자별 호출 / 2차: 기상청 API허브 격자 전체 자료로 전환 검토 | 시군구 대표 격자는 중복 제거 시 250개 이하라 일일 호출 한도 내. 전체 격자를 받으면 저장 장소 추천이 추가 호출 없이 가능 |
| 데이터 배포 | `main`에 커밋하지 않고 GitHub Pages 산출물에만 포함 | 3시간마다 커밋하면 `main` 이력이 오염되고 저장소가 비대해짐 |
| 천문 계산 | 일출·일몰·박명·월령은 클라이언트에서 계산(`suncalc`) | API 불필요, 좌표별로 정확 |
| 프론트엔드 | 빌드 도구 없는 순수 HTML/CSS/JS + D3(파일로 포함), 지도는 SVG path | Node 설치 없이 `python3 -m http.server`만으로 개발. 250개 폴리곤은 SVG로 충분, 색상 전환은 CSS transition |
| 보관 범위 | 어제 0시 ~ 단기예보가 제공하는 마지막 시각(약 4일 뒤, 마지막 하루는 3시간 간격) | 파일을 작게 유지. 지난 시각은 직전 파일에서 이어받음 |

### 4.3 데이터 스키마(안)
```jsonc
// weather_latest.json
{
  "baseTime": "2026-10-05T05:00+09:00",       // 예보 발표 시각
  "hours": ["2026-10-05T06:00+09:00", "..."], // 공통 시간축
  "grids": {
    "60,127": { "TMP": [..], "SKY": [..], "PTY": [..], "POP": [..], "REH": [..], "WSD": [..] }
  }
}
// regions.json : 시군구 코드 -> { name, sido, lat, lon, nx, ny }
```
* 값은 시간축과 인덱스가 일치하는 배열로 저장해 용량을 줄인다.
* 발표 시각(02·05·08·11·14·17·20·23시)을 화면에 표시해 데이터 신선도를 알 수 있게 한다.

### 4.4 지수 계산 (0~100점, `web/js/scores.js`)
대상 시간대가 아니면 점수를 내지 않고 지도를 회색으로 둔다. 비·눈이 오면 모든 모드가 최저점이다.

| 모드 | 대상 시간대 | 점수 요소 |
|---|---|---|
| 나들이 | 항상 | 강수확률, 기온(20℃ 전후가 만점), 풍속, 습도, 구름 |
| 일출·일몰 | 일출·일몰 전후 1시간 | 구름많음 > 맑음 > 흐림, 강수확률, 높은 습도 감점 |
| 은하수 | 태양 고도 -18° 아래(천문박명 이후) | 맑음, 떠 있는 달의 밝기 감점, 높은 습도 감점 |
| 운해 | 일출 2시간 전 ~ 1시간 반 뒤 | 높은 습도, 약한 바람, 밤사이 기온 하강폭, 위쪽 하늘 맑음 |

* 일출·일몰·달은 `suncalc`로 브라우저에서 계산한다.
* 한계: 단기예보의 하늘상태가 3단계뿐이라 구름 양을 세밀하게 반영하지 못한다. 은하수는 광공해를, 운해는 지형(고도)을 반영하지 않는다. 미세먼지도 아직 없다.

### 4.5 내 출사 후보지 입력
* 네이버 지도 연동은 하지 않는다(공식 내보내기 API 없음). **사용자가 직접 입력**한 장소 목록을 쓴다. 입력·저장 방식은 논의 중.
* 각 장소의 위경도를 격자 `(nx, ny)`로 변환해 같은 날씨 데이터에서 점수를 계산하고, 날짜·모드별 상위 N곳을 추천한다.

## 5. 구현 로드맵

### Phase 0 — 프로젝트 뼈대 ✅
* `web/`(정적 사이트), `scripts/`(Python 수집기, 표준 라이브러리만 사용), `tests/` 구조.

### Phase 1 — 전국 시군구 지도 ✅
* 시군구 경계 데이터 확보 → `mapshaper`로 단순화 → TopoJSON(1MB 이하).
* `d3-geo`로 SVG 렌더링, 호버 툴팁(시도 + 시군구명), 클릭 시 상세 패널, 확대/이동.
* **완료 기준:** 모든 시군구가 표시되고 이름이 정확히 나온다.

### Phase 2 — 격자 매핑과 수집기 ✅
* 위경도 ↔ 기상청 격자 변환(Lambert Conformal Conic) 함수를 Python·TypeScript 양쪽에 구현하고, 기상청 공개 예제 좌표로 테스트.
* `regions.json` 생성(시군구 대표점 → `nx, ny`). 대표점이 바다나 구역 밖에 떨어지는 경우 보정.
* 수집 스크립트: 고유 격자 중복 제거, 동시 요청 제한, 재시도, 일부 실패 시 직전 데이터 유지.
* **완료 기준:** 로컬에서 전국 `weather_latest.json`이 생성되고 누락 시군구가 0개.

### Phase 3 — 자동 갱신 (워크플로 작성 완료, GitHub에 올려 실제 실행 확인 필요)
* GitHub Actions 스케줄(발표 시각 + 약 15분), API 키는 Secrets로 관리.
* 수집 결과는 커밋하지 않고 Pages 산출물에만 넣는다. 직전 배포본의 데이터를 내려받아 지난 시각을 이어받고, 수집이 실패하면 배포하지 않아 기존 사이트가 유지된다.
* **완료 기준:** 사람이 개입하지 않아도 하루 8회 갱신된다.

### Phase 4 — 타임 슬라이더와 기본 히트맵 ✅
* 날짜 선택 + 시간 슬라이더(04~24시), 재생 버튼.
* 표시 변수 전환(하늘상태/강수확률/기온/풍속/습도), 범례, 색 전환 애니메이션.
* 시군구 상세 패널에 시간별 예보 표.
* **완료 기준:** 슬라이더를 움직이면 전국 지도가 끊김 없이 다시 칠해진다.

### Phase 5 — 출사·나들이 지수 ✅
* 4.4의 지수 4종 구현 및 단위 테스트, `suncalc`로 일출·일몰·월령 반영.
* 모드별 지도 색칠, "지금 조건에서 상위 10개 지역" 목록.
* **완료 기준:** 모드와 시간을 고르면 추천 지역 순위가 나온다.

### Phase 6 — 내 출사 후보지 추천
* 장소 직접 입력, 지도에 핀 표시.
* 날짜·모드 선택 시 후보지별 점수와 최적 시간대를 순위로 표시.
* **완료 기준:** 저장 장소 목록을 넣으면 "이번 토요일 일출 출사 추천 3곳"이 나온다.

### Phase 7 — 고도화(선택)
* API허브 격자 전체 자료로 전환해 읍면동·임의 지점까지 세분화.
* 중기예보(광역)로 4~10일 전망 보조 표시, 미세먼지, 광공해 지도, 모바일 레이아웃, PWA.

## 8. GitHub Pages 배포와 자동 갱신 가이드

배포 주소는 `https://kjso521.github.io/whether_weather/` 가 된다. (무료 요금제에서는 저장소가 **Public**이어야 Pages를 쓸 수 있다.)

### 8.1 동작 원리
```
[예약 실행 / main에 push / 수동 실행]
        │
        ▼
GitHub Actions (.github/workflows/deploy.yml)
  1. 저장소 코드를 내려받는다
  2. 테스트를 돌린다
  3. 지금 배포돼 있는 사이트에서 weather_latest.json을 내려받는다 (지난 시각을 이어받기 위함)
  4. scripts/collect.py 로 기상청에서 새 예보를 받아 합친다
  5. web/ 폴더를 통째로 Pages에 배포한다
        │
        ▼
https://kjso521.github.io/whether_weather/
```
* **서버가 없다.** GitHub이 빌려주는 임시 컴퓨터(runner)가 3시간마다 잠깐 켜져서 JSON 파일을 새로 만들고 꺼진다. 브라우저는 그 파일만 읽는다.
* **서비스 키는 코드에 없다.** 저장소의 Secret에 넣어 두면 실행할 때만 환경변수 `KMA_SERVICE_KEY`로 전달되고, 로그에서도 가려진다. 로컬의 `.env`는 `.gitignore`에 있어 올라가지 않는다.
* **날씨 데이터는 커밋하지 않는다.** `weather_latest.json`도 `.gitignore`에 있고, 배포물에만 들어간다. 그래서 커밋 이력이 3시간마다 늘어나지 않는다.
* **수집이 실패하면 배포하지 않는다.** 그 회차는 빨간 X로 끝나고, 사이트는 직전 데이터 그대로 남는다.

### 8.2 처음 한 번 설정하기
순서가 중요하다. 1~2번을 먼저 해 두어야 첫 실행이 성공한다.

**1) 서비스 키를 Secret으로 등록**
1. GitHub 저장소 페이지 → **Settings** → 왼쪽 **Secrets and variables** → **Actions**
2. **New repository secret** 클릭
3. Name: `KMA_SERVICE_KEY`, Secret: 공공데이터포털의 인증키(Encoding/Decoding 어느 쪽이든 됨) → **Add secret**

**2) Pages 배포 방식을 Actions로 지정**
1. **Settings** → 왼쪽 **Pages**
2. **Build and deployment → Source** 를 **GitHub Actions** 로 선택 (저장 버튼 없이 바로 적용됨)

**3) 코드를 올리기**
```bash
git status                       # 올라갈 파일 확인. .env 와 weather_latest.json 이 목록에 없어야 한다
git add .
git commit -m "전국 웨더맵 첫 버전"
git push origin main
```
* `git commit`에서 이름·이메일을 묻는 오류가 나면 한 번만 설정한다:
  `git config --global user.name "이름"` / `git config --global user.email "GitHub 가입 이메일"`
* `git push`에서 로그인을 물으면 GitHub 아이디와 **Personal Access Token**(비밀번호 아님)을 넣는다.

**4) 실행 확인**
1. 저장소의 **Actions** 탭 → "예보 수집 및 배포" 실행이 노란색(진행 중) → 초록 체크가 되면 성공 (2~3분)
2. 실행을 눌러 들어가면 `deploy` 작업 아래에 배포 주소가 표시된다
3. PC와 휴대폰에서 주소를 열어 확인. 메뉴 맨 아래의 "예보 발표 …" 시각이 최신이면 정상

### 8.3 자동 갱신 일정
`deploy.yml`의 이 부분이 일정을 정한다.
```yaml
schedule:
  - cron: "20 2,5,8,11,14,17,20,23 * * *"   # 분 시 일 월 요일 (UTC 기준)
```
* cron은 **UTC** 기준이다. 한국 시간은 UTC+9이므로, UTC 17:20 = 한국 02:20 이다.
* 기상청 발표 시각(한국 02·05·08·11·14·17·20·23시)은 3시간 간격이라, UTC로 바꿔도 같은 숫자 묶음이 된다.
* 발표 후 API 반영까지 시간이 걸려 20분 뒤에 돌린다. GitHub의 예약 실행은 혼잡하면 몇 분~수십 분 늦게 시작될 수 있다.
* 바로 갱신하고 싶으면 **Actions → 예보 수집 및 배포 → Run workflow** 로 수동 실행한다.
* 저장소에 60일 동안 활동이 없으면 GitHub이 예약 실행을 멈춘다. Actions 탭에서 다시 켤 수 있다.

### 8.4 문제가 생겼을 때
| 증상 | 확인할 것 |
|---|---|
| "예보 수집" 단계에서 실패, "서비스 키를 넣어 주세요" | Secret 이름이 정확히 `KMA_SERVICE_KEY` 인지 |
| "JSON이 아닌 응답" / "API 오류" | 키가 맞는지, 포털에서 활용 신청이 승인됐는지, 일일 호출 한도(회당 약 240회 호출)를 넘지 않았는지 |
| 격자 대부분이 시간 초과로 실패 | GitHub 서버(해외)에서 기상청 API 접속이 막혔을 가능성. 이 경우 수집을 내 컴퓨터에서 돌리는 방식으로 바꿔야 한다 |
| `deploy` 단계에서 실패 | Pages의 Source가 **GitHub Actions** 로 되어 있는지 |
| 사이트는 뜨는데 "데이터를 불러오지 못했습니다" | 그 회차의 수집이 실패했는지 Actions 로그 확인 |
| 휴대폰에서 옛 화면이 보임 | 브라우저 캐시. 새로고침하거나 몇 분 뒤 다시 열기 |

### 8.5 이후 수정 반영
코드를 고친 뒤 `git add . && git commit -m "설명" && git push` 하면 같은 워크플로가 다시 돌아 2~3분 뒤 사이트에 반영된다.
